# 🏗️ Архитектура системы

Технический справочник архитектуры, глубоких модулей, потоков данных и проектных компромиссов проекта `alice-jarvis`.

---

## 1. Сквозной поток данных (End-to-End Flow)

Система построена по гибридной архитектуре Edge-to-Cloud. Тракт распознавания речи (ASR) и синтеза (TTS) сохраняется за инфраструктурой Яндекса, а этап генерации смыслового ответа делегируется бессерверной языковой модели.

```
[Микрофонный массив Станции]
       │
       ▼ (аппаратная обработка Unisoc VQE: эхоподавление AEC, шумоподавление NS)
[Аудиоканал vqe_0]
       │
       ▼
[station-wakeword] ──детекция «Джарвис»──► эмуляция активации в демон maind
       │
       ▼
[aliced / maind] ──обращение к aliced.uniProxyUrl──► ws://127.0.0.1:8443/uni.ws
       │
       ▼
[quasar-bridge] (режим hybrid)
       │  1. Трансляция PCM-аудио в Яндекс Uniproxy
       │  2. Получение текстовой ASR-транскрипции
       │  3. Классификация намерения через routing.rules
       │
       ├──► Намерение yandex (погода, музыка, умный дом, таймеры) ──► Яндекс Uniproxy
       │
       └──► Намерение llm (обращение к Джарвису или default_route)
              │
              ▼ HTTPS POST /cf/v1/chat/completions (Bearer <JARVIS_KEY>)
       [Cloudflare Worker AI Proxy] (src/worker/cloudflare-proxy.js)
              │  Наложение системного промпта DEFAULT_SYSTEM (J.A.R.V.I.S.)
              ▼
       [Cloudflare Workers AI]
              │  Инференс: @cf/mistralai/mistral-small-3.1-24b-instruct
              │  Каскадный fallback: llama-3.1-8b-instruct ──► llama-3.3-70b-instruct
              ▼
       [quasar-bridge]
              │  1. Возврат текста ответа модели
              │  2. Формирование ответа для Яндекс TTS (озвучка родным голосом Алисы)
              │  3. Запись события в /data/opt/quasar-bridge/conversations.jsonl
              │
              ├──► mediad (воспроизведение аудио через усилитель и динамик)
              └──► jarvis-led (демон подсветки) ──► sysfs aw9110 (голубое дыхание 4..28с)
```

## 2. Модульная структура (Deep Modules)

Система разделена на независимые, слабосвязанные компоненты с минимальным внешним контрактом:

| Модуль | Исполняемая среда | Расположение | Контракт интерфейса |
| --- | --- | --- | --- |
| **`station-wakeword`** | Колонка (ARMv7) | `/data/wakeword/` | Захват `/dev/snd/pcmC0D0c` (`vqe_0`), HTTP UI `:8780`, программный триггер в `maind` |
| **`quasar-bridge`** | Колонка (ARMv7) | `/data/opt/quasar-bridge/` | WebSocket-сервер `:8443`, HTTP эндпоинт `/healthz`, файл журнала `conversations.jsonl` |
| **`jarvis-led`** | Колонка (ARMv7) | `/data/opt/jarvis-led/` | Асинхронный tail `conversations.jsonl`, запись в Linux sysfs `/sys/class/leds/` |
| **`cloudflare-proxy.js`** | Cloudflare Workers | Edge Network | REST API OpenAI-совместимого стандарта: `POST /cf/v1/chat/completions` (или внешний OpenAI-совместимый провайдер) |
| **`Workers AI / Any LLM`** | Cloudflare / Любой LLM API | Cloud / Local | Инференс LLM: Cloudflare (рекомендуется для РФ, 10 000 нейронов/сутки бесплатно) либо OpenRouter, Groq, DeepSeek, локальная модель |

## 4. Архитектура и жизненный цикл подсветки (`jarvis-led`)

### 4.1. Принцип изоляции (Decoupled Architecture)
Демон `jarvis-led` функционирует полностью изолированно от звукового тракта. Он не проксирует аудиопоток и не имеет блокирующих вызовов в цепочке синтеза речи. Взаимодействие осуществляется исключительно через асинхронный tail файла `conversations.jsonl`.

### 4.2. Обработка журнала и защита от гонок ротации
Компонент `tailer` (в `src/led/main.go`):
1. Сохраняет дескриптор открытого файла и байтовое смещение (`t.offset`).
2. При каждом цикле опроса (`poll()`) сверяет метаданные через `os.Stat`:
   - Если размер файла уменьшился (`fi.Size() < t.offset`), фиксируется ротация журнала мостом: дескриптор переоткрывается, смещение сбрасывается в начало нового файла.
   - Если строка в `conversations.jsonl` записана мостом частично (неполный JSON), `json.Unmarshal` завершается ошибкой, после чего вызывается `t.file.Seek(t.offset, io.SeekStart)` и `t.reader.Reset(t.file)`. Чтение строки откладывается до поступления символа `\n`.

### 4.3. Фильтрация событий
Демон реагирует исключительно на события:
```json
{"event":"response","route":"llm","text":"..."}
```
События штатных ответов Яндекса (`route == "yandex"`), таймеров, воспроизведения музыки, радио или событий отмены (`event == "cancel"`) демоном игнорируются.

### 4.4. Модель оценки длительности речи
Поскольку синтез TTS происходит асинхронно в облаке, длительность свечения рассчитывается программно исходя из количества символов ответа:
$$T = 2.5 + \frac{\text{len(runes)}}{14.0}$$
где:
- `2.5` с — фиксированное время сетевой буферизации и инициализации воспроизведения PCM-потока;
- `14.0` знаков/с — средняя скорость речи штатного диктора TTS Яндекса для русского языка;
- Длительность $T$ жёстко ограничивается диапазоном $[4.0\text{ с}, 28.0\text{ с}]$.

### 4.5. Визуальный профиль и аппаратный драйвер
- **Цветовая модель**: Равномерный голубой оттенок `RGB(40, 150, 255)`.
- **Функция дыхания**: Модуляция яркости по синусоидальному закону с базовой частотой 0.9 Гц:
  $$k(t) = 0.55 + 0.45 \cdot \left(0.5 + 0.5 \cdot \sin(2\pi \cdot 0.9 \cdot t)\right)$$
  Коэффициент $k(t)$ изменяется в пределах от $0.55$ до $1.0$, создавая эффект мягкой пульсации без резких скачков.
- **Аппаратный драйвер**: Контроллер AW9110, доступный через 9 sysfs-узлов ядра Linux:
  `/sys/class/leds/micro:{red,green,blue}:ring{1,2,3}/brightness` (диапазон 0..255).

### 4.6. Состояние покоя (Idle) и передача кольца Алисе
По истечении дедлайна таймера речи демон выполняет запись нулей (`RGB(0,0,0)`) во все 9 каналов sysfs. В состоянии покоя `jarvis-led` не выполняет записей в sysfs, полностью освобождая аппаратное кольцо под контроль системного демона `maind`. Все штатные анимации Алисы (фиолетовая волна активации, цветные уровни громкости, красный светодиод выключения микрофона, алерты таймеров) работают без помех.

### 4.7. Удаление устаревшего флага `-speed`
В ранних версиях демона передавался аргумент `-speed`. В актуальной реализации Go-пакета `flag` поддерживаются только флаги: `-log`, `-fps`, `-bright`, `-mode`, `-demo`, `-min`, `-max`, `-cps`.  
При передаче неизвестного ключа `-speed` вызов `flag.Parse()` аварийно завершает работу демона с кодом возврата `2` и сообщением:
```
flag provided but not defined: -speed
```
Init-скрипт `/etc/init.d/S99jarvis-led` очищен от устаревших аргументов и передаёт только действительный параметр `-bright "$bright"`.

## 5. Движок маршрутизации (`routing.rules`)

Классификация запросов выполняется `quasar-bridge` строго сверху вниз по списку правил до первого совпадения:

1. **`jarvis` $\to$ `llm`**:  
   Проверка наличия ключевых слов в тексте распознавания: `["джарвис", "jarvis", "гарвис", "жарвис"]`. Обеспечивает вызов модели при обращении через штатное слово активации «Алиса» («Алиса, спроси у Джарвиса...»).
2. **`yandex_services` $\to$ `yandex`**:  
   Исчерпывающий список регулярных выражений и ключевых слов для бытовых сценариев:
   - Управление умным домом: свет, люстра, розетка, шторы, кондиционер, увлажнитель, реле.
   - Информационные сервисы: погода, прогноз, температура, курс валют, новости.
   - Мультимедиа и таймеры: музыка, трек, песня, радио, таймер, будильник, секундомер, громкость, стоп.
   - Системные запросы: «который час», «сколько времени», «повтори».
3. **`pc_commands` $\to$ `yandex`**:  
   Команды управления компьютером (по умолчанию перенаправлены в Яндекс во избежание галлюцинаций LLM при отсутствии локального ПК-сервера).
4. **`default_route` $\to$ `llm`**:  
   **Критическое проектное решение**: При активации через аппаратный споттер `station-wakeword` ключевое слово «Джарвис» вырезается до попадания аудио в ASR-тракт. Текст транскрипции содержит только сам вопрос (например: «почему небо голубое»). Направление `default_route` в `llm` гарантирует, что любой вопрос после отдельного wake word направляется в языковую модель.

## 6. Сетевая устойчивость и оптимизация ресурсов

### 6.1. Предотвращение IPv6 Blackhole
Сетевой стек станции открывает TCP SYN-сегменты по IPv6 к доменам Cloudflare `*.workers.dev`, однако последующие пакеты данных отбрасываются оператором или ядром, вызывая 60-секундный таймаут моста. Скрипт `scripts/update_cf_pins.ps1` сопоставляет доменное имя воркера со статическими IPv4-адресами Cloudflare в файле `/etc/hosts`.

### 6.2. Отключение энергосбережения Wi-Fi (Unisoc Wi-Fi Power Save)
В скрипте запуска `src/bridge/start.sh` выполняется:
```sh
echo on > /sys/devices/platform/unisoc_wifi/power/control
```
По умолчанию контроллер Unisoc уходил в спящий режим между пакетами. Отключение энергосбережения снизило RTT с 71 мс до 9 мс и полностью устранило потери пакетов при передаче объемных POST-запросов к LLM.

### 6.3. Ограничения памяти Go Runtime
Общий объем оперативной памяти Яндекс Станции Лайт составляет 238 МБ, из которых значительная часть занята системными процессами Яндекса (`maind`, `mediad`, `telemetry`). В `runtime.env` зафиксированы жесткие параметры для предотвращения OOM-killer:
```sh
export GOMAXPROCS=1
export GOMEMLIMIT=64MiB
```

### 6.4. Защита от повреждения кодировки и переводов строк
- **CRLF в `runtime.env`**: Наличие байта `\r` (0x0D) приводит к невалидному значению `GOMEMLIMIT=64MiB\r` (паника Go) и передаче заголовка `Authorization: Bearer <KEY>\r` (ошибка 401 Unauthorized). Файл обязан содержать переводы строк строго в формате Unix LF.
- **UTF-8 в `config.json`**: Конфигурационный файл моста выгружается строго через `adb push`. Использование утилит PowerShell для сохранения текста может привести к повреждению кириллической таблицы символов, в результате чего правила маршрутизации перестанут совпадать.

### 6.5. Минимизация полезной нагрузки (Payload Size)
Параметр `dialogue_context.enabled` установлен в `false`. Это сохраняет размер HTTP POST-запроса к облаку в пределах 1 КБ (вместо 4–13 КБ при хранении контекста диалога), что критически важно для стабильности передачи данных по радиоканалу в условиях слабой зоны Wi-Fi.

## 7. Наблюдаемость и телеметрия

1. **Эндпоинт `/healthz`**:
   Возвращает текущий статус сетевого шлюза, счетчики обработанных пакетов и контрольный хеш `routing_revision`. Изменение `routing_revision` подтверждает успешное применение новых правил маршрутизации после перезапуска моста.
2. **Журнал `conversations.jsonl`**:
   Фиксирует каждое событие голосовой сессии с временной меткой Unix:
   - `request`: входящий запрос с указанием сессии;
   - `transcript`: полученный ASR-текст распознавания;
   - `response`: сформированный ответ, имя модели, длительность инференса и маршрут;
   - `cancel`: прерывание сеанса пользователем.
3. **Журнал `bridge.log`**:
   Фиксирует системные события уровня демона: решения классификатора `native_route_decision`, сетевые ошибки и активность watchdog.

## 8. Проектные компромиссы

1. **Однораундовый диалог (Single-Turn)**: Память контекста отключена для исключения таймаутов на медленных Wi-Fi-соединениях.
2. **Задержка ответа 2–3 секунды**: Компромисс в пользу бесплатного бессерверного облака без необходимости держать постоянно включенным домашний сервер или видеокарту.
3. **Облачный синтез Яндекса**: Обеспечивает идеальное произношение и знакомый голос Алисы, но делает систему зависимой от доступности серверов Яндекса.
