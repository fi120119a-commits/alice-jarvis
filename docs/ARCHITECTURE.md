# 🏗️ Архитектура

Документ описывает, из чего состоит проект и **почему** приняты те или иные
решения. Если вы хотите что-то поменять — начните отсюда.

## 1. Слои

```
[микрофон колонки]
      │  звук (канал vqe_0 — уже после эхоподавления)
      ▼
[wakeword]  услышал «Джарвис» → нажимает «слушать»
      │
      ▼
[облако Яндекса]  ASR (текст) + TTS (озвучка) — не заменяются
      │  ws://127.0.0.1:8443/uni.ws
      ▼
[quasar-bridge]  hybrid-режим, правила маршрутизации
      ├── route=yandex → тот же uni.ws (погода, музыка, таймеры, умный дом)
      └── route=llm    → HTTPS POST в Cloudflare Worker
      ▼
[Cloudflare Worker]  вшивает персонажа J.A.R.V.I.S.
      ▼
[Workers AI]  mistral-small → 8B → 70B (fallback)
      │
      ▼
текст → мост → Яндекс TTS → колонка говорит голосом Алисы
```

Ключевая идея: **не трогаем голосовой движок**. Алиса продолжает распознавать
и озвучивать, а понимание и генерация — наши. Поэтому качество голоса остаётся
яндексовским, а «мозг» можно менять одной строкой.

## 2. Компоненты

| Компонент | Где живёт | Роль |
| --- | --- | --- |
| `wakeword` | колонка | своё слово активации, веб-UI `:8780` |
| `quasar-bridge` | колонка | перехват тракта, маршрутизация |
| `jarvis-led` | колонка | голубое кольцо, пока Джарвис отвечает |
| Worker `cloudflare-proxy.js` | Cloudflare | персонаж, доступ к LLM |
| Workers AI | Cloudflare | сама модель |

ПК в рабочем пути **не участвует**. Он нужен только для установки и
обслуживания (ADB, деплой).

## 3. Файлы на колонке

```
/data/opt/quasar-bridge/
├── bin/quasar-bridge      бинарник (скачивается отдельно)
├── config.json            маршруты, LLM, логи
├── runtime.env            окружение: ключ LLM, лимиты памяти
├── start.sh               Wi-Fi power save off + запуск
├── bridge.log             технический лог (ротация 1 МБ)
└── conversations.jsonl    журнал разговоров (ротация 1 МБ × 2)

/etc/init.d/
├── S97wakeword
├── S99quasar-bridge       автозапуск + watchdog
└── S99jarvis-led

/system/vendor/quasar/quasar.cfg   ← сюда прописывается ws://127.0.0.1:8443/uni.ws
```

## 4. Маршрутизация

Правила проверяются по порядку, первое совпадение выигрывает:

1. **`jarvis` → `llm`** — в тексте есть «джарвис / jarvis / гарвис / жарвис».
2. **`yandex_services` → `yandex`** — погода, таймеры, музыка, новости, курсы,
   анекдоты, сказки и умный дом (свет, люстра, торшер, розетка, шторы…).
3. **`pc_commands` → `yandex`** — команды ПК; по умолчанию **выключены**
   (направлены в Яндекс, чтобы не уходили в модель).
4. **`default_route` = `llm`** — всё остальное.

Почему `default_route` именно `llm`: после срабатывания слова активации в
тексте распознавания слова «джарвис» уже **нет** — оно было «съедено»
демоном. Поэтому любой вопрос после wake word должен по умолчанию идти в
модель, иначе он уйдёт в Яндекс и вернёт «Я не поняла».

Правило `jarvis` нужно для случаев, когда вы говорите «Алиса, джарвис, …»
без wake word.

## 5. Облачный слой

`src/worker/cloudflare-proxy.js` — один файл без зависимостей:

| Маршрут | Что делает |
| --- | --- |
| `POST /cf/v1/chat/completions` | Workers AI + персонаж |
| `GET /cf/v1/models` | список моделей |
| `GET /cf/v1/warm` | диагностика прогрева (мс) |
| `/groq|gemini|openrouter/v1/*` | прокси к внешним API |
| `GET /healthz` | статус |

- Авторизация: `Authorization: Bearer <JARVIS_KEY>` (или `x-jarvis-key`).
- Персонаж — константа `JARVIS_SYSTEM`, вшивается в каждый запрос.
- Цепочка моделей: mistral-small → llama-3.1-8b-fast → llama-3.3-70b.
- `max_tokens` ограничен 220: голосовой ответ не должен быть длинным.
- Cron раз в 10 минут прогревает модель (страховка от выгрузки).

### Почему mistral-small, а не 70B

Замеры на бесплатном тарифе (один и тот же вопрос):

| Модель | Время |
| --- | --- |
| llama-3.3-70b | 12,4 с |
| mistral-small-3.1-24b | 2,4 с |
| llama-3.1-8b-fast | 1,4 с |

70B выдаёт 2–4 токена/с — для голоса это «задумалась и молчит». Mistral
сохраняет качество и укладывается в 2–3 секунды. 70B осталась последним
fallback'ом.

## 6. Подсветка кольца

`src/led/main.go` — отдельный демон, который **не участвует** в обработке
голоса и не может его замедлить. Схема:

```
quasar-bridge  --пишет-->  conversations.jsonl  --читает-->  jarvis-led  -->  sysfs
{"event":"response","route":"llm"}                            голубой      /sys/class/leds/micro:*
```

- Демон читает только новые строки (tail), старые ответы после перезапуска
  не подсвечиваются.
- Реагирует только на `event=response` и `route=llm`: ответы Яндекса, музыка,
  таймеры кольцо не трогают.
- Горит ровным голубым `rgb(40,150,255)` с «дыханием» 0.55–1.0; длительность
  `2.5 с + символы/14`, ограничена 4–28 секундами.
- В покое демон кольцо **не трогает**: анимации Алисы работают как обычно.
- Драйвер — `aw9110` через sysfs, три сегмента по три канала.

## 7. Сетевые решения

| Решение | Причина |
| --- | --- |
| IPv4-пины в `/etc/hosts` | IPv6 до `workers.dev` открывает соединение, но данные не идут → таймаут 60 с |
| `echo on > .../unisoc_wifi/power/control` | power save ронял крупные POST'ы; пинг 71→9 мс, потери 5→0% |
| `SSL_CERT_FILE=/system/vendor/quasar/ca-certificates.crt` | системные CA колонки |
| `GOMEMLIMIT=64MiB`, `GOMAXPROCS=1` | на колонке всего ~238 МБ RAM |
| `dialogue_context.enabled=false` | запрос ~1 КБ вместо 4–13 КБ: крупные POST'ы с колонки зависали |

## 8. Наблюдаемость

```powershell
# здоровье моста + хеш применённого конфига
adb shell "wget -q -O - http://127.0.0.1:8443/healthz"

# ответы: маршрут, текст, задержка
adb shell "grep '\"event\":\"response\"' /data/opt/quasar-bridge/conversations.jsonl | tail -5"

# решения маршрутизатора: rule или default
adb shell "grep native_route_decision /data/opt/quasar-bridge/bridge.log | tail -10"
```

`routing_revision` в `healthz` — хеш правил. Если после правки конфига он не
изменился, значит мост не перезапустился или прочитал старый файл.

## 9. Известные ограничения

1. **Задержка 2–4 с** — плата за бесплатное облако. Локальная модель была бы
   быстрее, но требует ПК.
2. **Нет памяти диалога** — контекст выключен ради стабильности. Включать
   только с маленьким `max_chars` (≤ 1500), иначе POST растёт и зависает.
3. **IPv4-пины нужно обновлять** при смене адресов Cloudflare —
   `scripts/update_cf_pins.ps1`.
4. **Нет резервного мозга** — если Cloudflare недоступен, мост через 60 с
   отдаёт фразу-заглушку. Резерв можно включить через Groq/Gemini/OpenRouter
   (ключи в секретах воркера).
5. **Голос — только Алисы.** Заменить TTS на мужской голос нельзя без
   переписывания голосового тракта: мост закрытый, а TTS — облачный.
6. **Root обязателен.** Без него нельзя ни поставить мост, ни переключить
   `quasar.cfg`.
